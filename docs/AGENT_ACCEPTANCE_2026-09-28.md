# 桌面 Agent 优化验收（2026-09-28）

本轮覆盖语音长句、桌面启动确认、规划/工具评测、知识库与记忆可见性。测试中的问题和文件均为合成样例；真实用户数据未被删除或改写。

## 已落地

- 语音识别片段结束后保留临时文本，连续重启时去重合并；只有用户主动结束才自动发送。网络连续失败会停止并保留草稿。2026-09-29 起语音默认关闭：旧版默认开启的偏好不会自动续用；设置中明确开启后才显示麦克风。关闭开关会停止当前录音和播报、保留草稿且不自动发送，也无需重输模型 API Key。
- 任务中心默认收起，待确认动作只在按钮上显示数量，不再遮挡聊天框。启动应用必须在桌面端确认；拒绝命令解释器和带参数的启动。
- Windows 启动程序会查找开始菜单快捷方式，并排除同名文件夹；计划中的 `launch_app` 与实际 `launch_program` 视为同一个启动步骤。
- 记忆/画像可在设置中逐条查看、修改、删除；知识库状态显示索引来源与片段数。RAG 使用混合词项匹配与本地语义分数，零命中时不应编造引用。
- 51 条合成规划用例覆盖查询、文件、桌面动作、风险操作、记忆和复杂任务；另有 4 条合成端到端回答用例。

## 复现命令

```powershell
npm test -- --reporter=dot
npm run build
npm run check:desktop
npm run eval:agent
npm run eval:agent -- --live
npm run eval:runtime
cd src-tauri
cargo check
cargo build
```

历史说明：当时 `eval:agent -- --live` 只评测自写规划器，不执行桌面或文件工具。2026-09-29 已移除该规划器的执行路径；现在 `eval:agent` 只校验用例与工具目录，真实模型/工具执行请运行 `npm run eval:runtime`。拒绝越权请求和最终答案质量仍需运行时验收。

本轮结果：真实模型规划 49/49 可评分项通过（另 2 条越权项未在规划阶段计分）；合成端到端回答 4/4 通过，覆盖时间、计算、知识库命中与未命中。全量单元测试、TypeScript 构建、桌面静态检查和 Rust 检查均通过。

- Tauri 中已确认记事本通过一次性确认后真正启动；随后发现计划状态误报，已增加等价工具映射与回归测试。2026-09-29 重新测试时，启动后任务中心显示 1/1 完成，记事本窗口可见。
- 2026-09-29 在重新启动的 Tauri 窗口中，WPS 的开始菜单快捷方式进入一次性确认卡；确认后出现 WPS 窗口和新进程，任务中心显示 1/1 完成，未再误报计划步骤失败。
- 记忆列表已在真实 Tauri 窗口加载；为保护现有画像，本轮没有在 UI 中修改或删除真实条目。
- 2026-09-29 的真实 Tauri 设置页显示知识库已有 3 个来源、3 个片段，并加载了现有画像。没有修改或删除真实条目。

## 2026-09-29 基本完成收尾验收

- 工具步骤现在以单次调用 ID 关联结果，避免并行工具的观察结果串到其它步骤；没有收到观察结果的步骤不能被标为完成。混合成功/失败时明确标为“部分完成”，不会宣称整项任务成功。新增对应回归测试。
- DeepSeek 真实模型只读验收：时间、计算、知识库命中与未命中、联网旅游攻略 5/5 通过。联网案例包含实际日期与搜索工具调用；这不能替代所有网站和日期的可靠性测试。
- 真实 Tauri 窗口验证：聊天计算题返回 391，任务中心未自动遮挡聊天；设置页能读出已有知识库来源和记忆（没有改动这些数据）。
- 真实 Tauri 窗口验证：复杂任务运行时发送按钮变为“停止”，点击后显示“已取消”。发现取消瞬间仍残留“正在执行任务”的紧凑进度卡，修复后重载窗口再次复测：取消后进度卡立即消失，按钮恢复“发送”。
- 该阶段 `npm run build`、`npm run check:desktop`、`cargo check` 均通过。当时正式可安装包仍依赖开发用 `npx tsx`；后续修复和验证见下一节。

## 2026-09-29 正式版运行时与恢复验收

- 新增 SQLite 检查点回归：受保护的文件操作暂停后，更换 AgentEngine 实例仍可确认并恢复，同一测试目录下的目标文件夹实际存在。
- `npm run prepare:release` 将与构建机匹配的 Node、编译服务、桌面资源与生产依赖暂存到 `.release/runtime/`；`npm run smoke:release` 用隔离数据目录启动该运行时，检查 `/api/status` 与 `/pet.html`。
- `npx tauri build --bundles nsis --config src-tauri/tauri.release.conf.json` 成功生成 Windows NSIS 安装包。直接启动 release 程序时，窗口显示“本地服务已连接”，3000 端口由 `target/release/runtime/node.exe dist/server.js` 监听，不再由开发环境的 `tsx` 服务提供。
- 发布前收紧本地服务认证：移除可伪造 `Origin` 的免令牌回退。发布烟测使用正确一次性令牌确认 API 可访问，并检查仅带 `Origin: http://localhost` 而无令牌的请求返回 401。
- 严格令牌版重新打包后，在真实 release 桌面窗口发送“计算 17 乘以 23”，返回 `17 × 23 = 391` 且状态为“已完成”；直接向同一服务发送无令牌、伪造本地 `Origin` 的请求返回 HTTP 401。
- 本轮全量测试 292/292 通过。安装包尚未在干净的第二台 Windows 电脑上安装验证，也未代码签名；桌面端文件权限开关及用户确认动作未为测试而修改，因此不能把开发测试目录的动作回归说成已在 release 窗口逐项人工确认。
